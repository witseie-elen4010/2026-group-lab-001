# ADR: Host application on Render

## Status
Accepted

## Context
The project requires a reliable hosting platform for the application, supporting automated deploys, TLS, logging, and environment configuration. Prior attempts to deploy to Azure encountered repeated environment and build configuration issues that increased setup time and required non-trivial platform-specific changes.

## Decision
We will host the application on Render.

Rationale:
- Rapid GitHub integration and automatic deploys on push reduce deployment overhead.
- Simple service configuration and clearer logs shorten feedback loops compared to recent Azure experiences.
- Built-in TLS, health checks, and centralized logs simplify operations.
- Render offers a 30-day free trial, allowing us to evaluate fit and costs before committing.

## Implementation
- Create a Render account and connect the GitHub repository.
- Provision a Render Web Service (or Docker service) and set the repository, branch, build, and start commands.
- Add environment variables and secrets in Render's dashboard.
- Enable automatic deploys for the main branches and configure deploy previews for feature branches as needed.
- Monitor performance, logs, and billing during the 30-day trial; document any provider-specific configuration.

## Consequences
- Benefit: Faster, less error-prone deployments and shorter developer feedback cycles.
- Risk: The 30-day trial requires cost evaluation before expiry; ongoing hosting costs must be approved by the team.
- Mitigation: Keep deployment instructions and build steps portable to reduce vendor lock-in and maintain an Azure fallback plan in documentation.

## Alternatives Considered
- Azure: Feature-rich and scalable, but our recent deployments encountered configuration and build issues that significantly increased setup time.
- Other providers (Heroku, DigitalOcean, AWS): Remain options if Render proves unsuitable after evaluation.
